# Skill: plan-roadmap

Purpose: turn a brief into outcome-based milestones.

Use when: roadmap is missing, stale, or no longer matches scope.

Do not use when: the requested work is a narrow implementation task with an accepted roadmap.

Inputs: `docs/product.md`, `project/brief.md`, current roadmap, requirements.

Procedure:

1. Identify outcomes, not feature lists.
2. Define milestone exit criteria and decision gates.
3. Keep only milestones relevant to the current project horizon.
4. Update requirements traceability if needed.

Outputs: updated `project/roadmap.md` and candidate tasks.

Allowed changes: roadmap, requirements traceability, task proposals.

Validation: `make validate-project`.
